# 環境探測程式

## 這是什麼

這**不是**正式的轉換程式，它不處理任何申請書、不讀取任何資料、也不會連上網路。

它唯一的工作，是檢查公務電腦能不能執行後續的正式程式，然後產生一份純文字報告。
在沒有系統管理員權限、又不確定有沒有軟體白名單管制的情況下，這件事必須先確認，
否則整個技術方向可能做到一半才發現走不通。

## 它會檢查什麼

| 項目 | 為什麼要測 |
| --- | --- |
| Windows 版本、CPU、記憶體 | 估算實際處理速度 |
| 幾個常用位置的寫入權限 | 正式程式要寫設定檔、樣板檔、診斷資料庫、輸出的 Excel |
| 含原生 DLL 的套件能不能載入 | 影像處理與 OCR 推論套件最容易被防毒誤判攔下 |
| 127.0.0.1 本機伺服器 | 人工複核介面的候選做法之一（純本機，不對外） |
| tkinter 視窗 | 人工複核介面的另一個候選做法 |
| 影像處理效能 | 用 A4 300dpi 的合成影像量測，推估每日批次要跑多久 |

報告內容只有這台電腦的環境資訊，**不含任何個人資料**，可以直接提供給開發者。

## 為什麼有四個版本

四個版本是為了在「跑不起來」的時候，能分辨到底是哪一種管制擋的：

| 檔案 | 差別 | 如果只有這個失敗，代表 |
| --- | --- | --- |
| `probe-lite-onefile.exe` | 只用 Python 標準函式庫，單一檔案 | — |
| `probe-lite-onedir` | 同上，但拆成資料夾 | — |
| `probe-full-onefile.exe` | 含影像處理與推論套件，單一檔案 | 精簡版能跑、完整版不能 → 是**防毒攔下原生 DLL** |
| `probe-full-onedir` | 同上，但拆成資料夾 | 單一檔案版不能跑、資料夾版能跑 → 是**暫存資料夾不准執行**的政策（單一檔案版會先解壓到暫存資料夾再執行） |

如果四個全部都開不了，那多半是 AppLocker 之類的執行白名單，正式程式就得改走瀏覽器路線。

## 怎麼測

1. 到 repo 的 **Releases** 頁面，下載 `probe-latest` 這一版的四個檔案。
   （也可以從 GitHub Actions 的 `build-probe-exe` 工作流程下載 `probe-exe` 產出物，
   但 Actions 產出物需要登入 GitHub 才下載得到，Releases 則是一般的下載連結。）
2. **先跑 `probe-lite-onefile.exe`**（在檔案上按兩下即可）。
3. 依上表的順序把其餘三個也跑一遍。
4. 每次執行都會在同一個資料夾（或桌面）產生一個 `環境探測報告_日期時間.txt`，把內容貼給開發者。

### 可能會遇到的狀況

- **「Windows 已保護您的電腦」** — 這是 SmartScreen，不是白名單管制。因為這個執行檔沒有購買程式碼簽章憑證。
  點「其他資訊」→「仍要執行」即可。
- **執行檔沒有反應，或立刻閃退** — 先在檔案上按右鍵 →「內容」→ 如果下方有「解除封鎖」就勾選後按確定，再試一次。
- **第 4 項會印出一個 `http://127.0.0.1:xxxxx/` 網址** — 請用瀏覽器打開，確認畫面上看得到 `PROBE_OK`，然後回到程式視窗按 Enter 結束。
- **視窗一閃就關掉，來不及看** — 不影響，報告已經存成 txt 檔了。

## 怎麼在本機重新建置

需要一台 Windows 電腦：

```
python -m venv venv
venv\Scripts\pip install -r probe\requirements-full.txt pyinstaller
venv\Scripts\pyinstaller --onefile --name probe-full-onefile probe\probe.py
```

或是直接改動 `probe/` 底下的檔案後推上 `claude/**` 分支，
`.github/workflows/build-probe.yml` 會自動在 Windows runner 上重新建置。
