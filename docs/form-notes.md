# 各表格的取值注意事項

七種表格的代號、來源，以及取值時容易搞錯的地方。
單純「哪一格對哪一欄」交給樣板設定，這裡只記錄光看版面看不出來的規則。

| 代號 | 表格 | 型態 | 內容 | 底圖來源 |
| --- | --- | --- | --- | --- |
| A | 地方稅線上申辦－案件處理（ETW820W） | 系統畫面列印 | 印刷字 | 不需要 |
| B | 稅務e平台－地價稅自用住宅用地稅率申請書 | 線上申請書 | 印刷字 | 不需要 |
| C | 房屋使用情形變更申報書（舊）`(民)稅房屋17-(民)表二` | 紙本手寫 | 手寫 | 影印件合成 |
| D | 房屋使用情形變更申報書（新） | 紙本手寫 | 手寫 | 影印件合成 |
| E | 中文主檔與通報檔比對資料清單 `LND149X_P04` | 系統報表 | 印刷字 | 不需要 |
| F | 地價稅自用住宅用地申請書（舊）`(民)稅土地02-(民)表一` | 紙本手寫 | 手寫 | 空白原稿 |
| G | 地價稅自用住宅用地申請書（新）`(民)稅土地02-(民)表一-1/2` | 紙本手寫 | 手寫 | 空白原稿 |

C、D 由其他單位送來，收到的一律是影印本。影印會帶來 1~3% 的縮放漂移與非線性變形，
所以原版空白表格對不上，底圖要從影印件本身合成。詳見 `tools/check_blank_alignment.py`。

## E：一頁上有三個地址，只取中間那一個

E 是橫式系統報表，掃進來是躺著的（程式會判定要順時針轉 90 度）。
版面上會出現三個看起來一模一樣的地址，意義各不相同，**取錯就是取到別人的資料**：

| 位置 | 意義 | 要不要取 |
| --- | --- | --- |
| `L1L2` 那一列**以上** | 申請人原來的地址 | 不取 |
| `L1L2` 那一列**以下第一個** | 申請人這次申請的房屋坐落 | **取這個** |
| `L1L2` 那一列**以下第二個** | 民眾要更址的地址 | 不取 |

樣本上承辦人的紅筆勾號正是勾在下排第一個，與上述一致。

三個地址的字面內容常常相同（同一個人沒搬家），所以**不能靠比對內容判斷取對了沒**，
只能靠位置。而且列數會隨資料筆數變動，**不能用固定座標**，
要以 `L1L2` 這個標記當錨點往下數 —— 樣板設定要支援錨點相對定位，不能只有固定框。

E 的地址是全形數字且含里、鄰
（例：`新北市鶯歌區尖山里００５鄰尖山路２７Ｏ號六樓`），
輸出前要照 `output-spec.md` 的規則轉成半形、去掉縣市區與里鄰。

## 紙本表格的門牌要拼起來，不能整段讀

C、D、F、G 的房屋坐落那一列，長這樣：

    房屋坐落： ____ 鄉鎮市區 ____ 路街  段 __ 巷 __ 弄 __ 號 __ 樓

**「路街」「段」「巷」「弄」「號」「樓」這些字是印在表格上的**，民眾只在空格裡
填值。所以把印刷版面減掉之後，手寫的部分只剩 `三峽　民生　147`，
沒有「路」也沒有「號」—— 不是辨識漏掉，是那些字本來就不是手寫的。

實測 F 表整段讀出來是 `三峡民生Q147`（Q 是民眾在「路」上畫的圈），
驗證會判「沒有『號』，可能沒讀完整」。

所以這幾種表格的門牌欄不能定成一個大框，要照印刷標籤切成好幾個小框
（路名、段、巷、弄、號、樓）分別辨識，再依規則組成 `民生路147號`。
A、B、E 那三種系統列印的表格沒有這個問題，地址是完整一串印出來的。

## 各表格取值的難易

以 F 表一件實測（辨識 + 正規化 + 驗證後）：

| 欄位 | 結果 | 說明 |
| --- | --- | --- |
| 段名 | 正確 | 手寫中文，字典可再加保險 |
| 地號 | 正確 | 數字，且有格式規則 |
| 行政區 | **靠字典救回來** | 辨識成「三山峡」，比對區名清單後修正為「三峽區」 |
| 門牌 | 要拼組 | 見上 |
| 身分證 | **驗證擋下** | 辨識錯，檢查碼不符，強制人工 |
| 姓名 | **錯且驗不出來** | 「陳一」讀成「陳」。姓名沒有字典也沒有格式規則， |
|  |  | 只能永遠列為必須人工確認 |

這個分布跟一開始的判斷一致：有字典或格式規則的欄位可以救，
身分證錯了會被檢查碼抓到不會靜默出錯，姓名是唯一「錯了也驗不出來」的欄位。
